# M1 tasks: the vertical slice, broken into pull requests

Status: proposed by the architect for review · 2026-11-17 · the contracts these tasks build against are
`docs/design/specs/2026-11-17-m1-architecture.md` ("the architecture file", cited as "A" plus a section, for example "A
3.7"). Sources: the design (`docs/design/specs/2026-11-16-unidex-rust-design.md`), the M0 gate report
(`docs/build/M0-GATE.md`), the threat model (`docs/security/THREAT-MODEL.md`), decision records 0001 to 0014, and the
maintainer's answers of 2026-11-17 to gate questions 1 to 5. A plan for builders is written from this file; it adds
step-by-step instructions, not new scope.

## Global constraints

Every brief carries these (design 11.2).

- **Privacy (design 12).** Public repository. No personal information in any file, commit, pull request, ledger line or
  agent report: no person's name, email address, account handle, home-folder path, host name or private network address,
  and no description of anyone's private setup. Write "the maintainer" and "the build team". Fixtures use `example.com`,
  `.test`, `.invalid` and `.example` names, the documentation address ranges, and invented names.
  `CI=1 cargo xtask privacy --all` must be clean before every commit; never bypass the commit hooks.
- **Provenance (design 11.4).** Read permissively licensed code as reference only; copy nothing from code under any
  other licence; do not read or describe the editor GPUI comes from beyond what decision 0007 says. A fragment adapted
  from permissively licensed code carries its attribution in a comment and in the third-party notices.
- **Contracts first (design 11.2).** The public items of the architecture file are created by T2 and changed only with
  the controller's agreement, written in the pull request. A builder who finds a contract unbuildable stops and reports;
  the controller amends the architecture file in its own small pull request.
- **Nothing is installed** on the development machine (a toolchain target, a tool, a model server) without the
  maintainer's approval, and nothing in M1 launches a browser.
- **Unverified external APIs.** Wherever the architecture file says "not verified", the task's first step verifies it
  against the pinned source or the vendor's published reference and records what it read in the pull request. If it is
  wrong, the task stops and reports before building on it.
- **Tests.** Every test writes only inside its test root (`UNIDEX_TEST_ROOT`, through `TestRoot` or `TestEnv`) and
  contacts no real service: providers run on recorded fixtures or the scripted mock provider, `web_fetch` on the
  loopback HTTP stand-in with a stub resolver. Live tests are opt-in (`UNIDEX_LIVE_TESTS=1`) and never run in CI. No
  test writes to the real OS secret store, registers OS state, or changes an ACL unless CI set the opt-in variable on
  its runner (A 3.1.1, `os_side_effects_allowed`). Nothing in M1 launches a browser or CEF.
- **Shared files.** These are edited only by the tasks named, so parallel tasks never collide:

  | File or folder | Edited by |
  |---|---|
  | `Cargo.toml` (root), every member's `Cargo.toml` dependency and feature tables, `Cargo.lock` | T2 only; a later need for a dependency stops the task and becomes a sequenced change. Exception: `[package.metadata.deb]` in `crates/udx-app/Cargo.toml`, by T29 |
  | `deny.toml` | nobody in M1 (any need stops the task) |
  | `privacy-allow.toml`, `.gitleaks.toml` | T1a, T1b, then T2 (which adds the entries for every vector file path reserved below); nobody after T2 |
  | `.github/workflows/ci.yml` | T1b, T4, T11, T31, never two at once |
  | New workflows | `governance.yml` (T1b), `sandbox-linux.yml` (T10), `ui.yml` (T28); `nightly.yml`: T1b (its concurrency group), then T29 |
  | `xtask/src/main.rs` | T1b, T29, T31, never two at once |
  | `crates/*/src/lib.rs` (module lists) | T2 only |
  | `crates/udx-app/src/main.rs`, `crates/udx-cli/src/main.rs` | T2 creates them; then T23 and T20 respectively, only |
  | `docs/build/LEDGER.md`, `docs/decisions/README.md` | the controller only, after each merge (M0 lost time to index conflicts) |

- **Decision record numbers are reserved** so parallel tasks do not collide: 0015 Linux sandbox (T10), 0016 Windows
  sandbox (T11), 0017 macOS sandbox (T9), 0018 the two providers (T8), 0019 session log format (T14), 0020 shaped-text
  cache (T27), 0021 widget kit for message bodies (T25), 0022 the `.deb` built with cargo-deb (T29), 0023 spend ledger
  (T15), 0024 HTTP and TLS stack (T6), 0025 governed-paths review (T1b), 0026 state root before the vault (T3).
- **One task, one branch, one pull request** in its own worktree, small enough to review in one read (design 11.2). At
  most two compiling agents run at once locally (design 11.3); document work runs beside them. `cargo check` before any
  full build; sccache on when available (decision 0007).
- **Roles (design 11.1).** Core builder: Opus, for the novel parts. Builder: Sonnet, for well-specified units. Test
  author: Sonnet, never the builder, writes failing tests from the contract first. Reviewer: Opus, reads the diff
  against this file and the architecture file without the builder's summary, and checks the builder's report against the
  diff (M0's lesson). Two failed Sonnet attempts escalate to Opus; two more stop the task and go to the maintainer.
- **Budgets** (gate report, section f, "Proposed budgets"), per task, all roles together, a hard stop that reports to
  the controller. Classes used here: code unit 1.0M (test author 150k, builder 300k, reviewers 500k, reserve 50k); the
  same class at the lower cap section f offers for small units, 0.7M (test author 100k, builder 250k, reviewers 300k,
  reserve 50k); core code 1.3M (re-split so a test author fits, as design 11.1 requires: test author 150k, builder 550k,
  reviewer 350k, fix agent 200k, reserve 50k); CI or packaging 1.3M (builders and test author 450k, reviewers 700k,
  reserve 150k); trial 1.3M (builder 600k, reviewer 250k, fix agent 300k, re-reviewer 100k, reserve 50k); document 0.6M;
  research document 1.2M; the gate's security review 0.5M. Fix rounds for agents above about 400k go to fresh agents
  with a findings file; large Opus agents run one at a time (gate report, "Pacing").
- **Done means** these pass locally on macOS and in CI on three platforms, plus the task's own commands:

  ```sh
  cargo fmt --all --check
  cargo clippy --workspace --all-targets --locked -- -D warnings
  cargo test --workspace --locked
  cargo deny --locked check
  CI=1 cargo xtask privacy --all
  ```

  CI also runs `cargo audit` and, for the crates in its scope, mutation testing; both must pass.
- **Platform evidence.** macOS is verified locally and in CI. Linux and Windows are verified in CI only (the maintainer
  has no Linux or Windows machine; gate question 24 is not answered). A pull request states which platform verified
  which test, and never claims a hands-on result nobody produced.
- **Screens.** A pull request that changes a screen attaches the `ui (macos)` job's frame artifact (design 10.1).
- **Repository settings.** New required checks are added to the ruleset by the maintainer; the task that creates a check
  says so in its pull request. Merges follow the repository's existing merge procedure.

## Wave 0: the first task of M1, then the contracts

The gate report requires every item of its section g, "The first task of M1: harden the privacy gate and the path
guard", in M1's first task. That is too large for one pull request, so the first task is three pull requests, T1a, T1b
and T1c, which together hold every item; nothing else starts before all three merge.

### T1a. Privacy gate: what it cannot see, and the false positive

- **Role and budget.** Sonnet test author, Sonnet builder, Opus reviewer. Code unit, 1.0M.
- **Needs.** Nothing. **Runs beside.** T1c.
- **Files.** Modify `xtask/src/privacy/scan.rs`, `xtask/src/privacy/rules.rs`, `xtask/src/privacy/git.rs`,
  `xtask/src/privacy/mod.rs`, `xtask/tests/privacy.rs`, `xtask/tests/privacy_mutants.rs`,
  `xtask/tests/github_committer.rs`, `privacy-allow.toml` (only if a vector needs it), `.cargo/mutants.toml` (only for a
  justified equivalent mutant).
- **Produces.** The same `cargo xtask privacy` interface, with wider coverage.
- **Items covered (gate report, section g).** UTF-16 content in every scan mode (`scan.rs:162-164`); host names beyond
  the one pattern: local network names, `user@host` prompts, IPv6 private and link-local addresses, hardware addresses
  (`rules.rs:74-75`); a home-folder path inside a URL's query string (`rules.rs:121-133`); a byte-order mark or UTF-16
  encoding in the private term list, which must fail loudly rather than silently disable terms (`scan.rs:43-55`,
  `mod.rs:155`); non-UTF-8 file names in the whole-tree mode (`git.rs:45-50`); submodule path names (`git.rs:94-95`); an
  empty range reported with the number of commits scanned, never a bare "clean" (`mod.rs:403-404`); allow-list values
  compared on the whole value, not a truncated excerpt (`mod.rs:140-142`); the home-folder rule anchored to the start of
  a path so a `home` or `users` module directory is not flagged (`rules.rs:53-54`); test vectors moved to reserved
  domains, keeping a real domain only where the rule under test is about that domain (the hosting service's no-reply
  address, the private-network host suffix), each with a comment saying why.
- **Tests** (failing first):
  - `utf16le_and_utf16be_files_are_scanned`: a personal term in a UTF-16 file (each byte order, with and without a BOM)
    is found in `--all`, `--staged`, `--range` and `--stdin`.
  - `local_network_names_flagged`: `nas.local`, `printer.lan`, a `user@host:~$` prompt line, `fe80::1`, `fd12:3456::1`,
    `00:1a:2b:3c:4d:5e` are each flagged; `example.com`, `::1`, `127.0.0.1` and a version string are not.
  - `home_path_in_query_string_flagged`: an `example.com` URL whose query string holds an invented user's home-folder
    path, plain and percent-encoded, is flagged (the vectors live in the test file, which the allow file covers).
  - `term_list_with_bom_or_utf16_fails_loudly`: a term list saved with a BOM is read correctly; one saved as UTF-16
    makes the scan exit 2 with a message, even without `--require-local`.
  - `non_utf8_file_name_scanned`: a file whose name is not UTF-8 is scanned and its name checked (Unix).
  - `submodule_path_name_checked`: a submodule at a path holding a personal term is flagged.
  - `empty_range_reports_zero_commits`: an empty range prints that zero commits were scanned and exits 0.
  - `allow_entry_must_match_whole_value`: an allow entry matching only the first 60 characters of a longer value does
    not exempt it.
  - `relative_home_segment_not_flagged`: a relative path with a `home` or `users` module folder is clean; an absolute
    home-folder path of an invented user, in the Unix and the Windows form, is flagged.
- **Done when.** The common commands, and `cargo mutants -p xtask --no-shuffle -j 2` locally with no missed mutant.
- **Platform notes.** UTF-16 and non-UTF-8 name tests run on all three CI platforms; the non-UTF-8 name test is Unix
  only (Windows file names are UTF-16), skipped with a printed notice on Windows.

- **Tests:**
  - `secret_patterns_flag_each_vector` and `secret_patterns_ignore_look_alikes` (placeholders such as `sk-ant-EXAMPLE`,
    hashes, UUIDs).
  - `pre_push_scans_pushed_range` (a commit made with `--no-verify` is caught at push),

  - `installer_refuses_global_hooks_path`, `installer_keeps_unreadable_hook`, `installer_keeps_non_utf8_hook`.

- **Done when.** The common commands; the three scratch checks above observed on CI and linked in the pull request.
- **Platform notes.** Hooks are tested on all three CI platforms (Windows runs them through Git's shell). The workflow

## Risks most likely to blow the budget (most likely first)

1. **The Linux and Windows sandboxes are CI-only work on unknown runner behaviour** (T10, T11). Whether the runner
   restricts user namespaces, the AppArmor profile syntax, cgroup delegation, AppContainer access entries and which
   tools run inside an AppContainer can each cost a CI round of ten or more minutes, and M0's trials show fix rounds of
   140k to 614k tokens. Mitigation: each task's "verify first" step runs on CI before the build; the controller stops a
   task at its cap rather than funding another round.
2. **Fix rounds from security reviews across many security tasks** (T5, T9 to T19). M0's reviews caught real holes in
   every security-relevant task (section f, "What the reviews caught"); a fix round is not funded by the 20 % margin.
   Mitigation: test authors write the threat model's tests first, so most findings are caught before review.
3. **The scroll target** (T24, T26b, T27). If shaping is not the main cause, the cache does not meet "at most 1 in
   1,000" and further work (row layout, tool rows) is unplanned; on a 120 Hz display the margin shrinks further.
   Mitigation: T24 measures before T27 is built, and T27 is re-scoped from its numbers.
4. **The gate's own cost** (T33). M0's gate cost 3.7M against 0.6M planned; 1.7M is capped here.
5. **GPUI churn in the app tasks** (T23, T26, T28, T31): pre-1.0 APIs, the test-support and profiler features, the
   Wayland hard check and three-platform UI jobs; mitigated by the cookbook patterns and the pinned source.
6. **Contract churn**: a signature in the architecture file that proves wrong in a later task costs a controller
   amendment and rework in every task built on it. T2's Opus builder and review are where this is cheapest to catch.
7. **Hosted macOS runner availability** (M0's repeated capacity messages) delays merges and re-runs.
8. **Question 23 answered late** delays T26b and T27; T26's minimal renderer keeps the rest moving.
9. **Usage-limit stops** (gate report, "Pacing"): large Opus agents run one at a time, re-reviews wait for fix rounds.
